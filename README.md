# C-Lab 学习计划

> 一句话原则：**一个项目长一年，不要一百个项目烂尾。**

## 为什么不做"每天一个新题目"

每天新建一个小程序，你会得到 30 个能跑的半成品，但没有一个能拿给别人用。
而在同一个项目上迭代 30 次，你会得到一个**能双击运行、能发给同学、能写进简历**的东西 ——
而且你被迫经历真正的软件开发过程：加新功能时怎么不把旧的弄坏、代码变长了怎么组织。

## 主线项目：STU-Tools（命令行版成绩与作业管理）

选它的原因：它的功能清单几乎等于《数据结构》的目录。
拥有一个自己真的会打开用的工具。

| 版本 | 做出来的功能 | 对应考点 | 能不能用 |
|------|-------------|---------|---------|
| v0.1 | 显示菜单，选 0 退出 | main、循环、switch | 能跑，但没内容 |
| v0.2 | 录入一门课的 N 个成绩并存到数组 | 数组、函数传参 | 能录能看 |
| v0.3 | 排序，输出最高/最低/平均分 | 冒泡 → 快排/归并 | **第一次真的有用** |
| v0.4 | 成绩条数不限，支持增删 | 链表（含头结点） | 不会再有"最多录几门"的限制 |
| v0.5 | 关掉程序再打开，数据还在 | 文件读写 fopen/fwrite | **第一次像真软件** |
| v0.6 | 按姓名或课程名查找 | 顺序查找 → 二分 → 哈希 | 记录多了也查得快 |
| v0.7 | 多门课、菜单补全、输入容错 | 综合调试 | 可以发给同学用了 |
| v1.0 | 打包 release，写 README | — | **你的第一个作品** |
| v1.1 | EasyX 画成绩柱状图 | 图形接口初步 | 有画面了 |

## 支线项目：每两周一个小游戏（练纯逻辑）

主线偏"翻译需求"，支线偏"算得对"。两条腿走路，按你说的两种都学。

1. 猜数字（循环 + 随机数）
2. 井字棋（二维数组 + 胜负判定）
3. 2048（二维数组移动合并，逻辑难点）
4. 贪吃蛇 · EasyX 版（真正的画面，第一次有"我做出来了个游戏"的感觉）

规则：**主线没推进，不许开支线。** 防止好玩的把重要的挤掉。

## 每天的流程（30–45 分钟）

1. **看一下今天的版本目标**（README 表格里的一行）
2. **先自己想，再动手**：把打算怎么写在纸上/注释里分 3-5 步写清楚（中文就行）
3. **卡住超过 15 分钟** → 才问 AI，而且用这句模板：
   > 我在写 XX 功能，我的思路是 ①…②…③…。现在卡在第 ② 步。
   > 不要给我完整代码，只告诉我这一步缺的是哪个知识点，以及为什么这样写不对。
4. **写完立刻 git commit**，一行说明今天改了什么
5. **今天回头记一句**：今天哪一行卡得最久 → 写进 PROGRESS.md，那就是明天要补的

## 三条纪律

- **AI 只做批改老师和提示员**，不做代写。它的产出你要合上默写才有效。
- **允许偷看，但必须合上再写。** Ctrl+C/V 跑通 = 当天白干。
- **每个版本都必须能编译出一个 exe 并双击能用。** 跑不动不许往下一版走。

## GitHub 节奏

从 v0.2 开始就 `git init`。一年后你的 profile 上会有一条从 v0.1 长到 v1.0 的绿线 ——
这比任何证书都能说明问题。
